# Identification workflow

## Purpose

OMIXIS Identification connects the quantitation feature table generated by MS-Aligner with experimental MS/MS spectra in the input mzML files. It uses the matched spectra as MS-FINDER queries and appends the resulting annotations and MSI evidence fields to a new feature-level TSV result. The original quantitation feature table is not modified.

## Required input

For an integrated OMIXIS run, provide:

- mzML files from one ion mode only (all positive or all negative)
- an MS-FINDER method file matching the instrument and ion mode
- an output folder

An authentic-standard list is optional. It is used for MSI evidence classification, not as the MS-FINDER candidate database.

The aligned feature table is generated automatically by the quantitation pipeline and is passed to Identification without user column mapping.

## Matching and annotation

1. Every MS/MS spectrum in the selected mzML files is written as an MSP file.
2. Each aligned feature is compared with MS/MS precursor m/z using `Ms1Tolerance` and `MassToleranceType` from the method file.
3. Feature RT is compared with MS/MS scan-start RT in minutes. `RetentionTimeTolerance` is used when present; otherwise the default is `0.02` min.
4. Each unique MSP matching at least one feature is sent to MS-FINDER once.
5. If a feature has several annotated MSP files, OMIXIS reports the annotation with the highest MS-FINDER Total score.

`RetentionTimeTolerance` controls OMIXIS feature-to-MS2 matching only. It does not control standard-list matching and is removed from the effective method file before MS-FINDER Console is launched.

## Standard-list matching and MSI evidence

When an authentic-standard list is supplied, OMIXIS compares each aligned feature with the standard m/z and RT values:

- standard-list m/z tolerance follows the MS-Picker `mzWidth` setting
- standard-list RT tolerance follows the MS-Aligner `rttol` setting (default `0.5` min)

These tolerances are independent of the method-file `RetentionTimeTolerance` used for feature-to-MS2 matching. Standard-list RT values must be expressed in minutes and should come from matching chromatography, polarity, and analytical conditions.

OMIXIS currently reports a simplified evidence classification:

- **Level 1**: the same feature has both an MS-FINDER compound annotation and a standard-list m/z/RT match
- **Level 2**: the feature has exactly one of those two evidence sources
- **Unknown**: the feature has neither evidence source

This rule combines evidence at the feature level. It does not independently require the MS-FINDER compound name or formula to equal the matched standard-list name or formula, so Level 1 rows should be reviewed before making a definitive identification claim. The standard list is not used as the MS-FINDER candidate database.

## Output

The Identification run folder contains:

- `Converted_MSP/`: MSP files converted from all experimental MS/MS spectra
- `mzML_to_MSP_manifest.tsv`: source mzML, scan, precursor, RT, and MSP-file mapping
- `MSFinder_Input_MSP/`: unique MSP files matched to at least one feature
- `Feature_MSP_matches.tsv`: every feature-to-MSP relationship
- `MSFinder_Result/`: original MS-FINDER output, when at least one MSP was submitted
- `MSFINDER_method_effective.txt`: the method passed to MS-FINDER
- `Untargeted_Compound_ID_Positive.tsv` or `Untargeted_Compound_ID_Negative.tsv`: final feature-level identification table

## Quality checks

Before interpreting annotations, review:

- whether all mzML files are from one polarity
- the number of converted MSP files, matched features, and identified features
- `Feature_MSP_matches.tsv` for m/z and RT errors
- `MSFINDER_method_effective.txt` to confirm the MS-FINDER search and database settings
- the run log/configuration to confirm the feature-to-MS2 and standard-list tolerances
- the final TSV for compound name, score, standard match, MSI level, and supporting evidence
